# QQ 会话缓存

连续触发的 QQ 对话可以复用进程内的 LangGraph checkpoint。空闲过期、达到容量或轮数上限后，整个旧代次被删除；下次触发从聊天数据库重建近期上下文。功能默认关闭，ACP 和定时任务保持独立执行。

## 启用与调整

在 Dashboard → 设置 → 会话缓存中开启 `enabled` 并保存。旧配置没有 `[sessions]` 时，页面也会显示默认值，保存时创建该配置段。也可手动编辑 `env.toml`，随后重启：

```toml
[sessions]
enabled = true
group_idle_seconds = 1800
private_idle_seconds = 7200
max_sessions = 128
max_generation_turns = 30
max_session_bytes = 67108864
max_total_bytes = 268435456
history_max_tokens = 32000
history_window_fraction = 0.25
cleanup_interval_seconds = 60
```

| 参数 | 含义 |
| --- | --- |
| `group_idle_seconds` / `private_idle_seconds` | 群聊／私聊上一轮结束后的空闲期限；默认 30 分钟／2 小时 |
| `max_sessions` | 进程中最多保留的会话数 |
| `max_generation_turns` | 同一代最多完成轮数；达到后释放，下一轮重建 |
| `max_session_bytes` / `max_total_bytes` | 单代／整个 saver 的序列化负载预算，单位 byte |
| `history_max_tokens` | 每次模型请求的跨轮历史 token 绝对上限，采用近似计数 |
| `history_window_fraction` | 跨轮历史最多占模型输入窗口的比例；还会扣除当前输入、系统提示、工具声明与响应余量 |
| `cleanup_interval_seconds` | 后台清扫周期；触发新请求时也会检查过期 |

所有数量、时长必须为正数；字节限制至少 1024，比例范围为 `(0, 1]`。未知模型 profile 使用最多 8000 token 的保守历史窗口。原有 `[storage].query_message_numbers` 仍限制每次 DB 查询的近期记录数；token 上限不会自动扩大数据库查询窗口。

Dashboard 保存后对新请求生效。配置修订变化会使下一轮重建；若在申请会话后、异步初始化期间重载配置，本轮安全终止，避免把旧状态交给不兼容的新图。运行中的图继续使用已创建的模型。关闭开关后，新请求走原来的历史路径，活动会话结算后回收；空闲会话由清扫器释放。

## 对话和投递语义

- 同一机器人、同一群的不同成员共享状态；不同机器人、群、私聊隔离。每轮重新绑定发言人和群角色。缓存不改变工作区文件权限。
- 当前请求仍然是唯一回复目标。历史只作背景，通过 DB 消息 ID 去重；每轮追加边界内的增量消息，包含未触发回复的群消息。
- 历史查询同时限制机器人、会话、当前消息 ID 和到达时间。机器人归属不明的旧记录不会加入缓存。
- 排队期间产生的助手回复不属于旧请求的快照。遇到这种冲突就删除热代次，在该请求原本可见的边界内重建；繁忙群聊因此可能频繁冷启动。
- `running` 和 `awaiting_delivery` 状态始终保留。图生成完成后，只有审核与发送完成才能结算；缓存里的最终 AI 消息按原 ID 替换成实际送达文本。
- 已发送但 DB 写入失败时不重发，热缓存保留送达事实；重启或冷重建后可能缺失这条未落库回复。
- 工件只提取当前轮输出。部分附件失败、文本发送失败、超时、取消、调用预算耗尽、工具写入结果不确定和人工中断都会使旧代次失效。下一轮重新构建背景，不自动续跑旧工具。
- `silent` 可以正常结束；下一轮重置静默标志、todos、用户和媒体输入。模型／工具调用预算和用量按新 run ID 独立统计。

## 容量与媒体

模型上下文裁剪和 checkpoint 存储回收分别处理。历史按完整对话轮次保留最近一段，工具调用与结果成对保留，当前轮输入不由历史裁剪器删除。Deep Agents 原有总上下文压缩继续工作；不导出其私有摘要事件，也不额外调用模型生成会话摘要。

`BoundedMemorySaver` 复用官方读写、恢复和整线程删除接口，不截断 DeltaChannel 的祖先链。计数包括 checkpoint 和 pending writes 的序列化负载，重复或覆盖写入继续计费直到删除整代，因此是保守上界，**不是进程 RSS 或 Python 对象堆大小**。

达到字节硬限的 75% 时提前轮换或淘汰空闲会话。活动会话不能被淘汰；所有会话繁忙或没有可用容量时，新请求使用无 checkpointer 路径。缓存初始化维护失败也可在模型执行前降级。图开始后遇到超大写入则返回 `checkpoint_capacity_exceeded` 并失效，不通过重新执行图绕过限制。

序列化时剥离 `ToolMessage.artifact`，当前轮仍保留真实 `UniMessage` 用于投递，不启用 pickle。包含输入／历史／工具多媒体或输出工件的轮次在结算后直接释放整个代次，避免二进制数据长期驻留。已有附件文件和数据库索引不受影响，后续通过原有附件路径与历史工具读取；附件过期沿用现有降级说明。

轮换采用惰性重建：结算时删除旧代次，下次触发才查询 DB 并创建新代次。没有额外常驻 `ConversationSeed`，也不保留旧图的任务调度现场。每轮 QuickJS 解释器使用 turn 模式，图取消后也显式执行清理，防止后台线程滞留。

## 观察与验证

Dashboard 总览显示开关、常驻会话数、复用／重建次数、序列化占用上限及快照冲突次数。`/api/dashboard/status/overview` 的 `agent_sessions` 还包含轮换、TTL/LRU 清理、容量／初始化降级、容量错误、历史 token 累计、历史准备耗时，以及运行／等待投递数量。累计值随进程重启清零；公开指标不包含 QQ 身份、聊天文本或工具参数。会话结算日志通过 run ID 关联本轮执行日志。

真实依赖契约位于 [checkpointer_test.py](../test/integration/checkpointer_test.py)，使用模拟模型和合成媒体，无付费模型调用。覆盖跨 28 轮 DeltaChannel 快照恢复、预算逐轮重置、实际 UniMessage 序列化与投递边界、子代理、取消和人工中断。144 轮合成压力测试经过 48 次轮换、24 次 LRU 淘汰和 24 次 TTL 清理后，存储计数回到零；一次本地运行的 RSS 从 166880 KiB 到 167144 KiB，未见随轮数持续积累的大对象。

单测另外覆盖并发全局写入预算、时钟、身份、增量去重、审核校准、投递失败、DB 写入失败与缓存维护故障。Dashboard 已通过模拟 API 下的桌面和移动端交互检查。上述验证不代表真实 QQ 账号或供应商服务的线上验收。

设计取舍和验收清单见 [实施计划](checkpointer-plan.md)。跨重启执行恢复、多进程共享、审批恢复和持久化摘要仍属于后续范围。
