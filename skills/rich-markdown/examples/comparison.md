# 小型机器人：本地模型与托管接口

先用实际对话验证效果，再结合数据要求、设备和维护时间选择部署方式。

::grid{columns=2}
::card{title="本地模型" color="blue" footer="重点检查设备与维护成本"}
推理服务由自己维护。可以控制部署位置和运行环境，但需要准备算力、监测资源并处理服务故障。
::
::card{title="托管接口" color="violet" footer="重点检查数据条款与接口限制"}
通过网络请求模型服务。无需维护推理硬件，但需要确认服务商的数据处理条款、费用与可用性。
::
::

## 用共同维度比较

| 维度 | 本地模型 | 托管接口 |
| --- | --- | --- |
| 运维责任 | 自己维护模型服务 | 服务商维护推理服务 |
| 网络要求 | 取决于本地部署与工具 | 调用接口需要网络 |
| 数据要求 | 自己管理服务边界 | 核对服务商的处理条款 |
| 成本核算 | 设备、用电与维护时间 | 调用费用及接入维护 |

::section{title="如何做出选择"}
如果当前目标是验证机器人是否有用，先选择自己能稳定运行的方式。收集真实请求，观察回答、耗时和故障，再判断是否值得更换部署。

**效果必须用实际任务验证**，不能仅根据“本地”或“托管”的标签推断模型能力。
::
